## Small recommended adoption set

Prefer maintained, version-pinned dependencies or services over copied platform code. Recommended deployment candidates: PostGIS, Keycloak (or approved equivalent OIDC after procurement), OpenTelemetry Collector, Prometheus, OpenSearch if the fixed benchmark passes, MapLibre renderer, and pg-boss. Development candidates: Synthea fixtures and official FHIR validator. ASR runtimes, OpenFGA, Temporal and middleware are later gated candidates. PostgreSQL/application framework dependencies are selected and pinned in M001; the donor landscape does not replace normal dependency qualification.

No direct-copy recommendation is approved. This is a deliberate answer to “which donors should contribute code”: use narrow upstream packages/services with their update channel; write Zyara's healthcare graph, authority-aware scheduling, eligibility, review governance and navigation policies natively. A copied component must beat this smaller approach with evidence before adoption.

## SpecGrain planning integration

User suggested SpecGrain during this mission. Inspected revision: **5de7d6499bb0a9e3a191fc0934399cf099d1980a**. [Evidence snapshot](../research/specgrain-evidence.json) includes six pinned files. The [domain contract](https://github.com/TheHalfMoon/SpecGrain/blob/5de7d6499bb0a9e3a191fc0934399cf099d1980a/docs/domain-model.md) distinguishes decomposition from dependency edges; [trust model](https://github.com/TheHalfMoon/SpecGrain/blob/5de7d6499bb0a9e3a191fc0934399cf099d1980a/docs/trust-model.md) separates executor report from independent evidence.

Adopt those methods in the handoff: bounded task scope, explicit risk/recovery, dependency DAG, immutable work-packet digest, observed change surface and revision-bound evidence. Larger tasks must be refined before execution. This mission creates portable planning contracts, not native SpecGrain state, and does not claim any task is a verified Grain.

The pinned README distinguishes published v0.3.0 from newer source-only shape/refine/grain commands and says that CLI path stops at GRAIN. Do not invent READY/execution/verification CLI support or infer benchmark superiority. The pyproject marks development status Alpha; optional tooling adoption requires M001 compatibility evaluation. No SpecGrain code was executed here.
